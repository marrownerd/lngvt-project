# Обновление Living Evidence Engine до v0.2

## Что добавлено

- Предварительное извлечение HR, RR, OR, IRR, 95% CI и p-value из аннотаций.
- Для каждой найденной оценки сохраняются PMID/DOI, URL, исходное предложение, смещения текста, тип источника и статус механической проверки.
- Загрузка доступного open-access full text из Europe PMC (JATS XML), включая текстовые абзацы и строки таблиц; локальный кэш в `data/open_access_cache/`.
- Совместимая миграция SQLite: при запуске `init_db()` в старой базе добавляется `pmcid`; существующие публикации не удаляются.
- Вкладка **Evidence & statistics**: таблица кандидатов, просмотр источников, CSV-экспорт и ручной запуск random-effects synthesis (REML или DL).
- Для синтеза доступны modified Hartung–Knapp 95% CI, pooled p-value, Q, I², τ² и приблизительный prediction interval при k ≥ 3.
- Вспомогательная функция Benjamini–Hochberg для заранее заданного семейства гипотез.

## Установка / обновление

Распакуй архив в отдельную папку или сохрани резервную копию текущего проекта. Не удаляй существующую папку `data/`: там находится твоя локальная база SQLite и журналы.

В терминале из корня проекта:

```bash
# Активируй своё виртуальное окружение, затем обнови зависимости
python -m pip install -r requirements.txt

# Проверка синтаксиса и тестов
python -m compileall -q .
python -m pytest -v

# Запуск приложения
python -m streamlit run app.py
```

При первом запуске новая версия автоматически добавит недостающий столбец `pmcid` в старую SQLite-базу. Резервная копия `data/longevity.sqlite3` перед обновлением всё равно рекомендуется.

## Как проверить новый workflow

1. Открой **Evidence & statistics**.
2. Сначала посмотри таблицу численных кандидатов, проверь source sentence и открой PMID/полную статью.
3. В блоке open-access можешь запросить XML из Europe PMC. Будут получены только записи, которые Europe PMC помечает как open access; paywall не обходится. Перед повторным использованием текста проверь лицензию конкретной статьи.
4. После получения текста таблица извлечения будет использовать кэшированный full text вместо аннотации.
5. CSV выгружает исходные фрагменты и поля извлечения для дальнейшей ручной проверки.
6. Статистический синтез запускай только после проверки первоисточников. Выбери совместимые оценки, задай единый outcome/estimand, популяцию, comparator, follow-up и design, затем подтверди независимость исследований и отсутствие пересекающихся когорт.

## Как читать статусы

- `mechanically_consistent` — распознанные estimate и CI прошли ограниченные арифметические проверки. Это **не** означает, что значение сверено с оригинальной таблицей или что исследование качественное.
- `review` — CI отсутствует, есть предупреждение или недостаточно данных для проверки.
- `invalid` — обнаружено противоречие или невалидные границы; такую строку нельзя использовать в статистической лаборатории.

SE рассчитывается из 95% CI на log-шкале с нормальным приближением. Оно подходит не для каждого способа построения интервала. Отсутствие результата у regex-парсера не означает отсутствия результата в статье.

## Ограничения этой версии

Извлечение пока не использует Quinex или полноценную LLM-схему; это baseline regex-парсер с ограниченным набором форматов. Он не распознаёт надёжно все типы эффектов, subgroup interactions, поправки на confounding, dose-response или все таблицы. `sample_size` и `follow-up` — текстовые подсказки, а не гарантированно корректные метаданные модели.

Pooling остаётся ручным. Программа не может автоматически проверить совместимость estimands, population, горизонтов, дизайнов и независимость когорт. HR/RR/OR/IRR — относительные меры, а не абсолютная разница рисков и не дополнительные годы жизни. Персональная survival/life-years модель в этой версии не реализована.

Следующий обязательный этап качества — benchmark с вручную размеченными медицинскими статьями и оценкой precision/recall каждого извлекаемого поля, а также независимая сверка метаанализа с другим статистическим пакетом.
